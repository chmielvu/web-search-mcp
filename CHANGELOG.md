### Fixed
- **Async orchestration rewrite — bounded cancellation drain** — `utils/async_helpers.gather_with_deadline()` previously waited forever for cancelled tasks to finish cleanup (`await asyncio.gather(*pending, return_exceptions=True)`).  A single provider whose httpx transport ignored cancellation could stall the entire pipeline indefinitely, causing every MCP tool call (`web_search`, `gemini_search`, `get_content`, etc.) to time out.  The rewrite introduces a bounded drain window (`DEFAULT_DRAIN_TIMEOUT_SECONDS = 3.0`, configurable per call).  After the main deadline expires, cancelled tasks are given the drain window to unwind; tasks that do not finish within that window are **abandoned**: a `_ignore_task_exception` done callback is attached to each so asyncio does not log "Task exception was never retrieved" warnings when the task eventually completes.  The `_collect()` helper now accepts an `abandoned` parameter and synthesises `CancelledError("abandoned after drain timeout")` entries for them, so callers always get a well-formed `(results, errors)` tuple regardless of whether tasks finished, were cancelled, or were abandoned.  The `task_completed_successfully()` helper remains unchanged — abandoned tasks are not `done()`, so branch-level and provider-level result collection naturally treats them as failures.
- **Async orchestration rewrite — shared HTTP client** — `search/pipeline.py` previously created and closed a new `httpx.AsyncClient` per `run_search_pipeline` call.  This was expensive (connection pool setup per request), prevented TCP connection reuse, and forced the orchestrator to coordinate client closure with in-flight cancellation cleanup.  The rewrite introduces `utils/http_client.py`, a server-level shared client module with three functions: `build_http_client()` (builds a configured client from settings), `get_http_client()` (lazy async singleton with double-checked locking via `asyncio.Lock`), and `close_http_client()` (idempotent shutdown).  The shared client is configured with `httpx.Limits(max_connections=200, max_keepalive_connections=50)` for connection pooling.  `pipeline.py` now calls `client = await get_http_client()` instead of `httpx.AsyncClient(...)`, and the `try/finally: await client.aclose()` block is removed entirely — the client outlives individual requests.
- **Async orchestration rewrite — FastMCP lifespan** — `server.py` now registers a FastMCP lifespan context manager (`_app_lifespan`) that yields on startup and calls `await close_http_client()` on shutdown.  This ensures the shared httpx client is closed cleanly when the MCP server exits, without relying on per-request lifecycle coordination.  The lifespan is passed to `FastMCP("web-search", lifespan=_app_lifespan, ...)`.
- **Async orchestration rewrite — test updates** — `tests/test_ab_wiring_rerank.py` (3 test methods) updated to patch `kindly_web_search_mcp_server.search.pipeline.get_http_client` (with `new_callable=AsyncMock`) instead of `kindly_web_search_mcp_server.search.pipeline.httpx.AsyncClient`.  `tests/test_async_helpers.py` expanded with `test_gather_with_deadline_abandons_tasks_that_ignore_cancellation` which verifies the bounded drain returns within `deadline + drain_timeout` even when a task catches `CancelledError` and sleeps indefinitely.  `tests/test_search_router.py::test_circuit_breaker_opens_on_failures` rewritten to exercise the circuit breaker tracker directly (`mark_failure_with_type` × 3 → `is_healthy` = False) instead of going through the slow `search_single_query` path (which takes 4-7 s per call due to OTLP span export overhead when the Grafana Cloud endpoint is unreachable — a pre-existing issue confirmed by `git stash` + run against the original code).
- **Pre-existing test fragility fixed** — `test_search_router.py::test_circuit_breaker_opens_on_failures` was already broken on the original code (confirmed by `git stash` + run).  Each `search_single_query` call took 4-7 s due to OTLP span export overhead when the Grafana Cloud endpoint is unreachable, causing the circuit breaker cooldown to expire before the assertion.  Rewrote the test to exercise the circuit breaker tracker directly (`mark_failure_with_type` × 3 → `is_healthy` = False), which is fast and deterministic.
